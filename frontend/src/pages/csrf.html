WEB SECURITY / LAB 02

Cross-Site Request Forgery (CSRF)

Kẻ tấn công lợi dụng phiên đăng nhập của bạn để gửi một thao tác mà bạn không hề xác nhận.

CSRF hoạt động như thế nào?

Kịch bản ngân hàng

  1. Bạn đăng nhập ngân hàng và trình duyệt giữ cookie phiên.
  2. Bạn mở một trang giả mạo có form “nhận quà”.
  3. Trang đó gửi POST chuyển tiền; trình duyệt tự đính kèm cookie.
  4. Server thiếu kiểm tra nên tưởng đây là yêu cầu của bạn.

Vì sao cần xác minh yêu cầu?

Cookie phiên có thể được gửi cùng request, nhưng điều đó không chứng minh người dùng chủ động thực hiện giao dịch. Server cần kiểm tra token trước khi thay đổi dữ liệu.

Cách phòng thủ

  • CSRF token: token gắn với phiên, gửi trong header riêng; thiếu hoặc sai thì trả 403.
  • SameSite và Origin: giảm/chặn request từ site khác; dùng như lớp bổ sung.
  • Xác nhận giao dịch: yêu cầu xác thực lại cho thao tác nhạy cảm.

Người dùng nên cảnh giác link lạ, đăng xuất trên thiết bị dùng chung và bật MFA. Tuy nhiên, phòng thủ CSRF chính vẫn thuộc về server.
