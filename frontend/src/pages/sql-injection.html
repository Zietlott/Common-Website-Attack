SQL Injection

Xem input làm thay đổi câu truy vấn đăng nhập ra sao, rồi thử lại cùng input với truy vấn tham số hóa.

SQL Injection là gì?

Kịch bản đăng nhập

  1. Website ghép username trực tiếp vào câu SQL.
  2. Kẻ tấn công gửi input có cú pháp SQL thay vì username bình thường.
  3. Database diễn giải một phần input như logic truy vấn.
  4. Trong lab, điều kiện đăng nhập bị vượt qua dù mật khẩu sai.

Hậu quả có thể có

Tùy truy vấn và quyền database, SQLi có thể làm lộ, sửa hoặc xóa dữ liệu; thậm chí bỏ qua đăng nhập. Lab này chỉ minh họa đăng nhập giả trên database demo chỉ đọc.

Cách phòng thủ

  • Prepared statement: tách câu SQL khỏi dữ liệu đầu vào.
  • Kiểm tra xác thực: tra tài khoản bằng tham số rồi kiểm tra mật khẩu bằng bcrypt.
  • Quyền tối thiểu: database chỉ có quyền cần thiết; không trả lỗi SQL nội bộ ra client.

Vì sao prepared statement chặn được input này?

Với placeholder, database nhận câu lệnh và giá trị riêng biệt. Dấu nháy hay từ khóa trong input chỉ còn là ký tự của username; sau đó mật khẩu vẫn phải khớp bcrypt hash. 

const user = db.prepare(
  "SELECT id, username, password, email FROM users WHERE username = ?"
).get(username);

if (!user || !(await bcrypt.compare(password, user.password))) {
  return loginRejected;
}
